# 04 Benchmark

这一步对应 `src/benchmark.py`，目标是比较 PyTorch 和 ONNX Runtime 的简单推理耗时。

Latency 指一次请求或一次推理从开始到结束的耗时，常用毫秒表示。Throughput 指单位时间内能处理多少请求或样本，例如 samples/s。推理系统通常既关心 latency，也关心 throughput：实时场景更看重单次响应速度，批处理场景更看重总体处理能力。

Benchmark 需要跑多次，是因为单次耗时很容易受到系统调度、缓存状态和初始化开销影响。代码里先做 warmup，再正式计时。warmup 的作用是让 Runtime、缓存、线程池等先进入比较稳定的状态，避免第一次运行的额外开销影响结果。

本项目的 benchmark 很简单：固定同一个输入，PyTorch 推理 1000 次，ONNX Runtime 推理 1000 次，然后计算平均 latency。这样可以帮助我建立性能测试的基本意识：固定变量、重复运行、统计平均值。

这个实验也有明显局限。模型太小，真实计算量很低，测出来的耗时可能主要来自 Python 调用和框架调度，而不是模型计算本身。它也没有测试不同 batch size、不同硬件、真实模型和并发请求。因此结果不能直接代表生产性能。它的价值在于让我开始理解推理性能指标，并知道后续要从模型规模、硬件后端、算子支持和运行时优化继续深入。
